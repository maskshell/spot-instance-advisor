# Release v1.1.0

**Release Date**: August 23, 2026

## 🆕 What's New

This release fixes two significant data-correctness issues in spot price analysis (incomplete API pagination and a non-functional `--resolution` window), hardens the tool against real-world API edge cases, and adds environment-variable credential support so your access key secret no longer needs to appear on the command line.

## ✨ New Features

### Environment Variable Credentials

Credentials now resolve in order: explicit flags → `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` → `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`.

```bash
export ALIYUN_ACCESS_KEY_ID=...
export ALIYUN_ACCESS_KEY_SECRET=...
./spot-instance-advisor --region cn-hangzhou
```

This keeps the secret out of argv, `ps`, shell history, and CI logs. Explicit flags still take precedence when both are set.

### Input Validation

Invalid flag combinations (e.g. `--limit -5`, `--mincpu 32 --maxcpu 1`, `--resolution 0`) now fail fast with a clear error instead of silently returning empty output. `--cutoff 0` is explicitly allowed as a "highlight only free instances" filter.

## 🐛 Bug Fixes

### Full Spot Price History Pagination

`DescribeSpotPriceHistory` results are now fully paginated via `Offset`/`NextOffset`. Previously only the first page was fetched — and the API returns the oldest entries first — so the "latest" spot price and the stability score were computed on a truncated, stale sample. Rankings are now based on the complete history for the configured window.

### `--resolution` Actually Works

The analysis window is now transmitted to the API (`StartTime`/`EndTime` computed in UTC with a past buffer to satisfy the API's `EndTime < now` rule). Previously the parameter was assigned after the request was sent and was silently ignored; the API's default window was used instead.

### Robustness

- Sold-out / out-of-stock zones no longer crash the tool (empty `AvailableResource` guard)
- A single malformed timestamp in the API response is skipped instead of terminating the run
- Instance types with incomplete metadata (missing CPU count or origin price, no valid timestamp) are excluded from the ranking instead of sorting to the top as bogus "best deals"
- `NaN` / `Infinity` values can no longer reach the table or JSON output
- Per-instance fetch failures print a warning to stderr (in both table and JSON modes); the tool errors out only when every instance type fails
- Runtime errors print a clean message (a JSON error object in `--json` mode) and exit 1, instead of dumping a Go stack trace via `panic()`

## 🔄 Migration Notes

The CLI surface and JSON output schema are unchanged — existing scripts and workflows continue to work without modification. **Output values may differ from v1.0.3**: rankings are now computed over the complete price history and the configured `--resolution` window takes effect, so prices and stability scores are more accurate than before.
