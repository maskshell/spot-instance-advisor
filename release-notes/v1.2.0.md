# Release v1.2.0

**Release Date**: August 24, 2026

## 🆕 What's New

Automatic retry with exponential backoff for transient Aliyun API failures. Since v1.1.0 fetches the *complete* spot price history (full pagination), each run makes more API calls than before — so a single throttled response must no longer silently drop an instance type from your results. This release makes those transient failures recover automatically.

## ✨ New Features

### Transient-Failure Retry with Backoff

Retryable failures — HTTP 429, server-side 5xx, `Throttling`/`FlowControl` error codes (which the API can also return with HTTP 400), and request timeouts — are now retried up to 3 times with exponential backoff (1s → 2s → 4s, capped at 10s):

- **Per-call granularity, including mid-pagination**: a throttle striking while fetching page 3 refetches only that page — pages already fetched are kept, and pagination continues.
- **Both timeout shapes matched**: the SDK-wrapped `SDK.TimeoutError` (AutoRetry-enabled configs) and the raw transport timeout (`*url.Error` / `net.Error`) the default configuration actually returns.
- **Fail fast on non-transient errors**: invalid parameters, auth failures, and endpoint misconfiguration are not retried — one attempt, clear error, no wasted time.
- **Observable**: every retry is logged to stderr (`--json` output on stdout stays clean).

### Example

```
Warning: DescribeSpotPriceHistory(ecs.g6.large) hit a transient failure (attempt 1/4), retrying in 1s: ...
```

## 🔄 Migration Notes

Fully backward-compatible — no CLI or JSON schema changes. The only observable difference: instance types that previously vanished from results due to a single throttled/timeout response now appear as expected. In the worst case (persistent throttling) a single API call may take up to ~7 extra seconds across its retries before giving up with a warning.
